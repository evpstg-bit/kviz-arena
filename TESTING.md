# Проверки проекта

Этот документ объединяет отдельные TESTING-REPORT-файлы. Записи истории ниже сообщают о проверках, выполненных на указанных версиях; они не означают, что все сценарии автоматически повторно проходят на каждом новом коммите.

## Базовые проверки перед публикацией

1. Проверка серверного синтаксиса: `node --check server.js`.
2. Извлечение встроенных JavaScript-блоков из `public/index.html` и проверка каждого через `node --check`.
3. Разбор JSON-файлов: `package.json`, `app-settings.json`, `builtin-tests.json` и пример JSON-теста.
4. Проверка CSS-файлов: `public/ui.css`, `public/liquid-glass.css`, `public/responsive-v2.css`, `public/tailwind.css`, `src/input.css`.
5. HTTP smoke-тесты: `/`, `/api/info`, CSS-ресурсы, фавиконы, XLSX и QR-код библиотека.
6. Проверка основного пользовательского пути: вход преподавателя, открытие библиотеки, импорт одного и нескольких файлов, создание папки, ручная сортировка тестов, запуск обоих режимов, завершение матча и просмотр/экспорт отчёта.

## Результаты последних регрессионных проверок

### Color Kingdoms — v1.11.3
- Проверены синтаксис `server.js`, встроенные скрипты `public/index.html`, JSON-файлы и целостность ZIP-архива.
- Локальный интеграционный сценарий: создать комнату, подключить 30 игроков, отключить часть SSE-соединений, запустить матч и проверить, что комната остаётся живой и переходит в состояние игры.
- HTTP smoke-тесты для главной страницы, `/api/info` и responsive CSS завершились успешно.
- Полный визуальный тест в браузере и проверка живого Render-деплоя не выполнялись.

### Classic — проверка запуска с 30 участниками
- Локальный тест создал комнату на 30 игроков; часть SSE-потоков была закрыта до старта.
- После нажатия старта ведущий получил состояние вопроса, ответ участника был принят, а комната осталась доступна после рассылки.
- Баг, при котором закрытие части SSE-подключений могло прервать старт/рассылку, в этом сценарии не воспроизвёлся. Это проверка конкретного сценария, а не гарантия отсутствия всех ошибок.

### Ранее проверявшиеся области
- Для v1.11.0 выполнялись синтаксические проверки JavaScript, разбор JSON и CSS, HTTP smoke-тесты, проверка размеров поля для групп разной численности.
- Для сортировки папок выполнялись API-сценарии сохранения порядка, проверки чужих/лишних идентификаторов и изоляции тестов вне выбранной папки.
- Для глобальных настроек проверялись чтение/сохранение настроек и использование параметров при создании новой комнаты.
- Для отчётов проверялись граничные случаи порога 40%, включая 4/10 = 40% (не попадает в «Где возникли трудности») и 17/43 = 39,5% (попадает).
- Для навигации и меню выполнялись проверки синтаксиса, CSS/JSON, HTTP-ресурсов и переходов назад/вперёд.

## Регрессионные сценарии, которые стоит проверять вручную

- Classic: запуск с несколькими участниками, ответы, следующий вопрос, рейтинг, завершение и отчёт.
- Color Kingdoms: распределение по командам, размеры поля, правильные/неправильные ответы, выдача флагов, захват клеток, длительность 5–20 минут и определение победителя.
- Переподключение: отключение одного клиента и повторное подключение без потери активной комнаты.
- Авторизация и права доступа: пользователь без входа не должен управлять библиотекой/отчётами; редактирование доступно только администратору.
- Мобильная вёрстка: ширина 320–430 px, светлая/тёмная темы, меню, диалоги, редактор и экраны игры.

## Автоматизация

В репозитории пока не обнаружен настроенный GitHub Actions workflow, который запускал бы весь набор проверок при каждом push. Дальнейшее улучшение — добавить CI-workflow и вынести ключевые API-сценарии в воспроизводимые тесты.
