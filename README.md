# Квиз-арена

Платформа для интерактивных викторин в вузе. Преподаватель запускает тест, студенты подключаются по PIN-коду и отвечают со своих устройств.

В этой сборке добавлен визуальный слой **Liquid Glass**: полупрозрачные панели, мягкие цветовые ореолы, блики на гранях и размытые поверхности. Он оформлен в отдельном файле `public/liquid-glass.css`, подключённом после базовых стилей; игровая логика и переводы не меняются.

Ведущий во время игры видит отдельную **панель статистики участников**: статус онлайн/офлайн, текущий статус ответа, общий счёт, число правильных ответов, точность и режимные показатели. Список обновляется через Server-Sent Events; исключение игрока требует подтверждения и немедленно отключает его от комнаты. Убраны служебные сообщения о синхронизации библиотеки с GitHub из экрана входа.

## Библиотека тестов

- Все тесты хранятся в `builtin-tests.json` в корне проекта.
- Администратор может импортировать `.xlsx`, `.xls` или совместимый `.json` прямо из личного кабинета.
- При импорте Excel-файл читается в браузере, преобразуется в формат игры и передаётся серверу. Сервер записывает результат в `builtin-tests.json`; тесты появляются в библиотеке без ручного копирования JSON.
- В карточке теста доступны **Запустить**, **Редактировать**, **Копировать** и **Удалить**. Изменения тоже записываются в `builtin-tests.json`.
- Если настроены `GITHUB_TOKEN`, `GITHUB_REPOSITORY` и `GITHUB_BRANCH`, сервер автоматически сохраняет изменения коммитом в GitHub. Render затем может автоматически задеплоить новый коммит.
- Если GitHub-синхронизация не настроена, сервер изменяет файл в рабочей папке. Кабинет дополнительно скачивает обновлённый `builtin-tests.json`, чтобы его можно было заменить в репозитории вручную. На Render без GitHub-синхронизации файл в работающем контейнере не гарантированно сохранится после нового деплоя.

## Формат XLSX

Один лист Excel = один тест. Поддерживается шаблон из `examples/primer-voprosov.xlsx`: строка заголовков содержит `Question` / `Вопрос`, `Answer 1`…`Answer 4` / `Вариант 1`…`Вариант 4`, `Time limit` / `Время` и `Correct answer(s)` / `Правильные ответы`. Заголовки могут находиться ниже инструкций на первых строках. В колонке правильных ответов указывайте номера вариантов с единицы (`2` или `1,3`) либо буквы `A`–`D`. Пустые или некорректные строки пропускаются с сообщением о замечаниях.

## GitHub auto-sync (рекомендуется для Render)

В Render Dashboard → сервис → **Environment** добавьте:

- `GITHUB_TOKEN` — fine-grained GitHub token с доступом **Contents: Read and write** только к нужному репозиторию;
- `GITHUB_REPOSITORY` — `владелец/имя-репозитория`, например `my-account/kviz-arena`;
- `GITHUB_BRANCH` — ветка, связанная с Render, обычно `main`.

Не помещайте токен в код, JSON или Git. Задавайте его только в защищённых переменных окружения Render. После изменения переменных перезапустите сервис. На локальном Codespaces без этих переменных сервер всё равно пишет проектный файл; затем выполните Commit & Push из Codespaces.

## Запуск

Требуется Node.js 18+. Зависимости для запуска не нужны:

```bash
node server.js
```

Откройте `http://localhost:3000`. Вход администратора задаётся через `admin-credentials.json` (в этом архиве настроены логин `bntu` и пароль `230825`). Для публичного проекта не храните пароль в открытом виде в репозитории.

## Структура теста

```json
{
  "app": "kviz-arena",
  "version": 2,
  "items": [
    {
      "id": "test-example",
      "quiz": {
        "title": "Пример",
        "T": 20,
        "mode": "classic",
        "dur": 5,
        "need": 3,
        "q": [
          { "t": "Столица Франции?", "a": ["Берлин", "Париж", "Рим", "Прага"], "cs": [1], "T": 20 }
        ]
      }
    }
  ]
}
```

Старый формат `{ "title": ..., "q": [...] }` внутри `items` тоже поддерживается. `cs` — индексы правильных вариантов с нуля (`[1]` — второй вариант, `[0,2]` — первый и третий).

## Выбор режима игры

Режим не назначается при импорте XLSX. В библиотеке нажмите «Запустить», затем выберите Classic или Color Kingdoms. Выбор относится только к текущему запуску и не изменяет вопросы теста. Диалог выбора переведён на русский, английский и китайский языки.

## Отчёты преподавателя

После завершения игры ведущему автоматически открывается подробный отчёт. Вернуться к сохранённым результатам можно через **Кабинет преподавателя → Отчёты**.

В отчёте доступны:

- **Общая статистика**: участники, вопросы, количество и доля правильных/неправильных ответов, средние баллы и самые сложные вопросы.
- **Участники**: индивидуальные баллы, ответы, правильность и точность; подразделы «Все участники», «Нуждаются в помощи» (точность ниже 60% или ни одного ответа) и «Статистика по командам».
- **Вопросы**: каждый вопрос, количество ответов и распределение ответов по вариантам с выделением правильных.
- **Экспорт Excel**: сводка, участники, вопросы и команды — если режим использует команды.

Отчёт создаётся при штатном завершении игры или при досрочном завершении ведущим. Отчёты доступны тому преподавателю, который провёл игру, и администратору.

### Где хранятся отчёты

Отчёты записываются в ``DATA_DIR`` как `reports.json` (по умолчанию в каталог `data`). Они намеренно не записываются в GitHub-репозиторий: отчёты содержат имена и индивидуальные результаты студентов, которые не следует случайно публиковать в репозитории.

**Важно для Render Free:** файловая система бесплатного сервиса временная. Отчёты доступны после игры, но могут исчезнуть при замене экземпляра или повторном развёртывании. Для постоянной истории нужен поддерживаемый Render постоянный диск, смонтированный в сервис, и переменная `DATA_DIR`, указывающая на каталог внутри точки монтирования, либо внешняя база данных. Не используйте публичный Git-репозиторий как хранилище персональных результатов студентов.
