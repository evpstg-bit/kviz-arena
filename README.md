# Квиз-арена — версия 1.12.24

Платформа для проведения интерактивных викторин в вузе. Преподаватель запускает игровую комнату, студенты подключаются по PIN-коду или QR-коду и отвечают со своих устройств.

**Текущая версия берётся из `package.json`.** Скрипт `scripts/version-sync.js` синхронизирует номер в заголовке этого файла, версионные параметры кэша в `public/index.html` и клиентское значение версии. GitHub Actions запускает синхронизацию после изменения `package.json` в ветке `main`; при необходимости скрипт можно запустить вручную.

## Возможности платформы

### Игровые комнаты и режимы

- Подключение участников по шестизначному PIN-коду и QR-коду.
- Режим **Classic**: вопросы с таймером, очки, бонус за скорость и рейтинг участников.
- Режим **Color Kingdoms**: командная игра с интерактивным полем, территориями и флагами; длительность матча настраивается в пределах 5–20 минут.
- Режим выбирается после нажатия «Запустить» и применяется к конкретной игровой сессии, а не записывается в импортированный тест.
- Преподаватель видит онлайн-статус, состояние ответов, баллы и точность участников; может исключать участника из комнаты.
- Обновления игрового состояния и статистики поступают в реальном времени через Server-Sent Events.

### Библиотека тестов

- Библиотека хранится в `builtin-tests.json`; тесты доступны для запуска, редактирования, копирования и удаления.
- Поддерживается импорт одного или нескольких файлов `.xlsx`, `.xls` и совместимого `.json`.
- Один лист Excel соответствует одному тесту. Импортированные тесты можно сразу поместить в выбранную папку предмета.
- Папки можно создавать, переименовывать и удалять. При удалении папки сами тесты сохраняются и перемещаются в «Без папки».
- Поддерживаются сортировка по названию и ручное изменение порядка тестов.
- Изменения библиотеки сохраняются в `builtin-tests.json`. При настроенной GitHub-синхронизации сервер автоматически коммитит изменения в репозиторий.

### Формат таблицы Excel

В одном листе должна быть строка заголовков со столбцами:

- `Question` / `Вопрос`;
- `Answer 1`…`Answer 4` / `Вариант 1`…`Вариант 4`;
- `Time limit` / `Время`;
- `Correct answer(s)` / `Правильные ответы`.

Заголовки могут находиться ниже инструкций в начале листа. Правильный ответ указывается номером варианта с единицы (`2`, `1,3`) или буквой `A`–`D`. Пустые и некорректные строки пропускаются с сообщением о замечаниях. Пример таблицы находится в `examples/primer-voprosov.xlsx`, если этот файл присутствует в текущей ветке репозитория.

### Настройки и отчёты

- Раздел «Настройки» централизованно управляет доступностью игровых режимов, базовыми баллами, бонусом за скорость, длительностью Color Kingdoms, временем по умолчанию, лимитом участников и поведением отчётов.
- Настройки применяются к новым игровым сессиям; активная комната продолжает работать со значениями, сохранёнными при её запуске.
- После игры формируется отчёт с общей статистикой, результатами участников, анализом вопросов и командной статистикой там, где она применима.
- Отчёты можно повторно открыть из кабинета преподавателя и экспортировать в Excel.
- В отчётах есть вкладки участников и вопросов, включая выделение сложных вопросов и участников, которым нужна помощь.
- Отчёты содержат персональные результаты и хранятся отдельно от Git-репозитория в каталоге `DATA_DIR` (по умолчанию `data`).

### Интерфейс

- Адаптация для мобильных телефонов и планшетов, портретной и альбомной ориентации, узких экранов и безопасных областей устройств.
- Светлая и тёмная темы; выбор языка интерфейса: русский, английский и китайский.
- Выбор темы и языка размещён во всплывающем меню.
- Навигация кабинета включает библиотеку, отчёты, настройки, действия импорта/экспорта, переходы назад/вперёд и выход.
- Оформление Liquid Glass вынесено в отдельный слой стилей; есть адаптивные стили и фавиконки для браузеров и устройств Apple.
- Лобби обновлено: отдельные карточки QR-кода и ссылки, крупный PIN, понятный список подключившихся участников и адаптивная кнопка старта; компактная компоновка помогает видеть основные элементы без прокрутки на типичных экранах; экран ожидания студента также переработан.
- Внизу страниц указан копирайт `© eyefront` со ссылкой на [Instagram](https://www.instagram.com/eyefront/).

## Запуск локально

Требуется Node.js 18 или новее. Для запуска сервера дополнительные npm-зависимости не нужны.

```bash
node server.js
```

Затем откройте [http://localhost:3000](http://localhost:3000).

Для синхронизации номера версии вручную выполните:

```bash
npm run version:sync
```

Скрипт читает версию из `package.json` и обновляет заголовок README, версионные параметры favicon/CSS и клиентское значение версии в `public/index.html`.

## Развёртывание на Render

Рекомендуется связать Render с GitHub-репозиторием и веткой `main`, включив автоматическое развёртывание после коммитов. GitHub Actions синхронизирует номер версии, а Render может развернуть полученные коммиты автоматически.

Для сохранения библиотеки тестов и глобальных настроек между развёртываниями добавьте в Environment сервиса Render:

| Переменная | Назначение |
|---|---|
| `GITHUB_TOKEN` | GitHub token с правом **Contents: Read and write** для нужного репозитория |
| `GITHUB_REPOSITORY` | Полное имя репозитория в формате `владелец/репозиторий` |
| `GITHUB_BRANCH` | Ветка для сохранения изменений, обычно `main` |
| `DATA_DIR` | Необязательно: каталог постоянного диска или другого постоянного хранилища данных |

Не помещайте токен или пароль администратора в исходный код, README или Git. Храните секреты в защищённых переменных окружения. Учётные данные администратора задаются отдельно в конфигурации сервера; перед публикацией проекта убедитесь, что используются собственные безопасные данные.

### Постоянное хранение

- `builtin-tests.json` и `app-settings.json` синхронизируются с GitHub, если заданы три переменные `GITHUB_*`.
- Без GitHub-синхронизации изменения в рабочей папке Render могут потеряться при повторном развёртывании.
- Файл `reports.json` и другие данные из `DATA_DIR` не следует коммитить в публичный репозиторий: они могут содержать персональные данные студентов. Для постоянного хранения используйте постоянный диск Render или внешнюю базу данных.

## Обновление версии

1. Измените поле `version` в `package.json`, например с `1.12.11` на `1.12.12`.
2. Отправьте изменение в ветку `main`.
3. GitHub Actions запустит `scripts/version-sync.js` и создаст отдельный коммит, если в README или интерфейсе есть устаревшие значения.
4. После этого Render сможет автоматически развернуть обновлённую ветку.

Перед коммитом можно запустить `npm run version:sync` локально. Скрипт идемпотентен: повторный запуск не меняет уже синхронизированные файлы. История точных изменений кода доступна в [истории коммитов GitHub](https://github.com/evpstg-bit/kviz-arena/commits/main).

## Журнал изменений

Краткая история релизов находится в [CHANGELOG.md](CHANGELOG.md). Не создавайте отдельный файл журнала для каждой небольшой правки: добавляйте заметки в существующий журнал, а подробный diff оставляйте в истории Git.
