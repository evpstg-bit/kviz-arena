# Квиз-арена — версия 1.17.17

Платформа для проведения интерактивных викторин в вузе. Преподаватель запускает игровую комнату, студенты подключаются по PIN-коду или QR-коду и отвечают со своих устройств.

**Текущая версия берётся из `package.json`.** Скрипт `scripts/version-sync.js` синхронизирует номер в заголовке этого файла, версионные параметры кэша в `public/index.html` и клиентское значение версии. GitHub Actions запускает синхронизацию после изменения `package.json` в ветке `main`; при необходимости скрипт можно запустить вручную.

### Стартовая пауза и обратная связь

- Перед началом каждого режима показывается общий отсчёт от пяти секунд.
- Правильный ответ и распределение ответов доступны только преподавателю.
- В Classic рейтинг показывается только преподавателю; начисленные за вопрос баллы и общий счёт плавно анимируются.
- Участник видит только «Верно» или «Неверно». При правильном ответе показываются начисленные баллы и обновление личного счёта; правильный вариант неверного ответа не раскрывается.

### Результаты без всплывающих окон

Автоматические всплывающие окна после ответа удалены. Преподаватель видит правильные ответы, распределение ответов и рейтинг на странице результатов. Правильный вариант выделяется ярко и отмечается галочкой; неверные варианты приглушаются. Отдельная текстовая строка с повтором правильного ответа не выводится. Участник получает встроенную обратную связь «Верно/Неверно», а правильный ответ не раскрывается.

### Полноэкранный игровой экран

- После нажатия ведущим кнопки «Начать игру» браузер открывает игровой экран в полноэкранном режиме, если браузер поддерживает Fullscreen API.
- Выйти можно крестиком в правом верхнем углу или клавишей Esc. Полноэкранный режим запрашивается именно нажатием на кнопку запуска, поскольку браузеры блокируют такие запросы из фоновых событий.

### Всплывающий рейтинг после вопроса

После того как все участники ответили (или закончилось время вопроса), преподаватель сначала 6 секунд показывает правильный ответ, выделенный в основном интерфейсе. Затем появляется всплывающее окно общего рейтинга Top-10 ещё на 6 секунд с анимацией очков. После этого платформа автоматически открывает следующий вопрос. Участники рейтинг не видят.

### Последовательность после вопроса

Сначала правильный вариант выделяется на экране преподавателя на 6 секунд. После этого открывается всплывающий Top-10 на следующие 6 секунд. По завершении обоих этапов игра автоматически переходит к следующему вопросу. Оба этапа запускаются после всех ответов или по окончании таймера вопроса.

### Оригинальное звуковое сопровождение

В игре добавлены синтезированные мелодии без сторонних музыкальных записей: пятисекундный обратный отсчёт с нарастающими сигналами, лёгкая фоновая тема во время вопроса или раунда, короткие сигналы правильного и неправильного ответа, отдельные музыкальные акценты при показе правильного ответа и Top-10, а также финальная мелодия. Звук включён по умолчанию и отключается кнопкой «Звук» на игровом экране. На мобильных устройствах воспроизведение активируется после первого касания экрана из-за ограничений браузеров.

### Регулировка громкости музыки

На игровом экране рядом с кнопкой включения/выключения звука доступен ползунок громкости от 0 до 100%. Уровень сохраняется в браузере отдельно для каждого устройства. Начальная громкость увеличена; синтезированные мелодии стали заметнее.

## Возможности платформы

### Игровые комнаты и режимы

- Подключение участников по шестизначному PIN-коду и QR-коду.
- Режим **Classic**: вопросы с таймером, очки, бонус за скорость и рейтинг участников. В топ-10 показаны общий счёт и очки, заработанные каждым участником за текущий вопрос. После ответа всех игроков или окончания таймера на 3 секунды показывается центральное окно рейтинга, затем следующий вопрос открывается автоматически; после последнего вопроса всем участникам автоматически открываются общие итоги: подиум топ-3 и рейтинг остальных игроков.
- Режим **Color Kingdoms**: командная игра с интерактивным полем, территориями и флагами; можно выбрать от 2 до 4 королевств. У каждого королевства собственный цвет, цветные ладьи и отдельная статистика. Участники распределяются максимально равномерно: разница между командами при старте не превышает одного человека; новые участники направляются в наименее заполненное королевство. Длительность матча настраивается в пределах 5–20 минут.
- Если до окончания матча башня в последнем раунде не захвачена, победителем этого раунда становится королевство с наибольшим количеством занятых клеток; за уникальное лидерство оно получает трофей. На итоговом экране отдельно показан победитель последнего раунда по клеткам, а победитель всего матча по-прежнему определяется количеством трофеев.
- Режим выбирается после нажатия «Запустить» и применяется к конкретной игровой сессии, а не записывается в импортированный тест.
- Преподаватель видит онлайн-статус, состояние ответов, баллы и точность участников; может исключать участника из комнаты.
- Обновления игрового состояния и статистики поступают в реальном времени через Server-Sent Events.

### Библиотека тестов

- Библиотека хранится в `builtin-tests.json`; тесты доступны для запуска, редактирования, копирования и удаления.
- Поддерживается импорт одного или нескольких файлов `.xlsx`, `.xls` и совместимого `.json`.
- Один лист Excel соответствует одному тесту. Импортированные тесты можно сразу поместить в выбранную папку предмета.
- Папки можно создавать, переименовывать и удалять. При удалении папки сами тесты сохраняются и перемещаются в «Без папки».
- Поддерживаются сортировка по названию и ручное изменение порядка тестов.
- Изменения библиотеки сохраняются в `builtin-tests.json`. При настроенной GitHub-синхронизации сервер автоматически коммитит изменения в репозиторий.

### Формат таблицы Excel

В одном листе должна быть строка заголовков со столбцами:

- `Question` / `Вопрос`;
- `Answer 1`…`Answer 4` / `Вариант 1`…`Вариант 4`;
- `Time limit` / `Время`;
- `Correct answer(s)` / `Правильные ответы`.

Заголовки могут находиться ниже инструкций в начале листа. Правильный ответ указывается номером варианта с единицы (`2`, `1,3`) или буквой `A`–`D`. Пустые и некорректные строки пропускаются с сообщением о замечаниях. Пример таблицы находится в `examples/primer-voprosov.xlsx`, если этот файл присутствует в текущей ветке репозитория.

### Настройки и отчёты

- Раздел «Настройки» централизованно управляет доступностью игровых режимов, базовыми баллами, бонусом за скорость, длительностью Color Kingdoms, временем по умолчанию, лимитом участников и поведением отчётов.
- Настройки применяются к новым игровым сессиям; активная комната продолжает работать со значениями, сохранёнными при её запуске.
- После игры формируется отчёт с общей статистикой, результатами участников, временем прохождения теста, анализом вопросов и командной статистикой там, где она применима.
- Отчёты можно повторно открыть из кабинета преподавателя и экспортировать в Excel — как по одному, так и несколько отмеченных отчётов одним файлом с отдельными листами сводки, участников, вопросов, вариантов ответов и команд. Время прохождения показывается в сводке и Excel. При каждом открытии истории приложение заново проверяет индекс постоянного хранилища, чтобы восстановить список после перезапуска сервера.
- В отчётах есть вкладки участников и вопросов, включая выделение сложных вопросов и участников, которым нужна помощь.
- Углублённый анализ помечает малую выборку и досрочные сессии, выявляет частые неверные варианты, низкую долю ответов и потенциально обратное разделение сильной и слабой части группы. Диагностика основана на фактических ответах и выдаёт проверяемые педагогические шаги; она не выдаёт предположения о причинах ошибок за установленные факты.
- Отчёты содержат персональные результаты и хранятся отдельно от Git-репозитория в каталоге `DATA_DIR` (по умолчанию `data`).

### Интерфейс

- Адаптация для мобильных телефонов и планшетов, портретной и альбомной ориентации, узких экранов и безопасных областей устройств.
- Светлая и тёмная темы; выбор языка интерфейса: русский, английский и китайский.
- Выбор темы и языка размещён во всплывающем меню.
- Навигация кабинета включает библиотеку, отчёты, настройки, действия импорта/экспорта, переходы назад/вперёд и выход.
- Оформление Liquid Glass вынесено в отдельный слой стилей; есть адаптивные стили и фавиконки для браузеров и устройств Apple.
- Участник, пришедший по QR-коду, попадает в отдельный экран входа и затем видит только игру и итоги; главная страница, меню платформы и кнопки возврата убраны, а результаты сохраняются при обновлении страницы в той же вкладке.
- Для аккаунта преподавателя доступна двухфакторная аутентификация TOTP: подключение Google Authenticator по QR-коду, обязательный код при входе и 8 одноразовых резервных кодов. Зашифрованный секрет хранится в отдельной ветке постоянного GitHub-хранилища; переключение 2FA отзывает старые сессии. Управление этой функцией находится в разделе «Настройки».
- Лобби обновлено: отдельные карточки QR-кода и ссылки, крупный PIN, понятный список подключившихся участников и адаптивная кнопка старта; компактная компоновка помогает видеть основные элементы без прокрутки на типичных экранах; экран ожидания студента также переработан.
- Внизу страниц указан копирайт `© eyefront` со ссылкой на [Instagram](https://www.instagram.com/eyefront/).

## Запуск локально

Требуется Node.js 18 или новее. Для запуска сервера дополнительные npm-зависимости не нужны.

```bash
node server.js
```

Затем откройте [http://localhost:3000](http://localhost:3000).

Для синхронизации номера версии вручную выполните:

```bash
npm run version:sync
```

Скрипт читает версию из `package.json` и обновляет заголовок README, версионные параметры favicon/CSS и клиентское значение версии в `public/index.html`.

## Развёртывание на Render

Рекомендуется связать Render с GitHub-репозиторием и веткой `main`, включив автоматическое развёртывание после коммитов. GitHub Actions синхронизирует номер версии, а Render может развернуть полученные коммиты автоматически.

Для сохранения библиотеки тестов и глобальных настроек между развёртываниями добавьте в Environment сервиса Render:

| Переменная | Назначение |
|---|---|
| `GITHUB_TOKEN` | GitHub token с правом **Contents: Read and write** для нужного репозитория |
| `GITHUB_REPOSITORY` | Полное имя репозитория в формате `владелец/репозиторий` |
| `GITHUB_BRANCH` | Ветка для сохранения изменений, обычно `main` |
| `REPORTS_ENCRYPTION_KEY` | Стабильный секрет для шифрования отчётов; не меняйте его без переноса зашифрованных отчётов |
| `AUTH_SECURITY_ENCRYPTION_KEY` | Отдельный случайный секрет длиной не менее 32 символов для шифрования настроек Google Authenticator. Не храните его в Git и не меняйте после подключения 2FA |
| `DATA_DIR` | Необязательно: каталог постоянного диска или другого постоянного хранилища данных |

Не помещайте токен или пароль администратора в исходный код, README или Git. Храните секреты в защищённых переменных окружения. Учётные данные администратора задаются отдельно в конфигурации сервера; перед публикацией проекта убедитесь, что используются собственные безопасные данные. Для двухфакторной аутентификации дополнительно задайте `AUTH_SECURITY_ENCRYPTION_KEY` — отдельный случайный секрет длиной не менее 32 символов в Environment сервиса Render. Настройки 2FA шифруются этим ключом в файле `auth-security.enc.json` в ветке `REPORTS_BRANCH`; не удаляйте и не меняйте ключ, иначе нельзя будет расшифровать секреты приложения. Он не влияет на шифрование существующих отчётов.

### Постоянное хранение

- `builtin-tests.json` и `app-settings.json` синхронизируются с GitHub, если заданы три переменные `GITHUB_*`.
- Без GitHub-синхронизации изменения в рабочей папке Render могут потеряться при повторном развёртывании.
- Файл `reports.json` и другие данные из `DATA_DIR` не следует коммитить в публичный репозиторий: они могут содержать персональные данные студентов. Для постоянного хранения используйте постоянный диск Render или внешнюю базу данных.

## Обновление версии

Используется формат `MAJOR.MINOR.PATCH`; для каждой правки кода версия повышается в соответствии с её масштабом:

- **PATCH** (например, `1.12.27 → 1.12.28`) — исправление ошибки, визуального дефекта, регрессии или небольшая техническая корректировка без добавления заметной возможности.
- **MINOR** (например, `1.12.28 → 1.13.0`) — новая функция или существенное совместимое расширение возможностей платформы.
- **MAJOR** (например, `1.12.28 → 2.0.0`) — несовместимое изменение или крупная переработка, меняющая основные правила работы платформы.

При каждом обновлении необходимо:
1. Выбрать следующий номер по правилам выше и изменить `version` в `package.json`.
2. Добавить запись в начало `CHANGELOG.md` с новой версией, датой и кратким перечнем изменений.
3. Синхронизировать заголовок этого файла и версионные параметры кэша/резервный номер в `public/index.html`. Для этого запустите `npm run version:sync`; GitHub Actions также выполняет синхронизацию после изменения `package.json` в ветке `main`.
4. Зафиксировать все файлы версии и изменения кода в репозитории. Если Render связан с веткой `main` и автоматическое развёртывание включено, платформа получит эти изменения через очередной деплой.

Скрипт синхронизации идемпотентен: повторный запуск не меняет уже синхронизированные файлы. История точных изменений кода доступна в [истории коммитов GitHub](https://github.com/evpstg-bit/kviz-arena/commits/main).

## Журнал изменений

Краткая история релизов находится в [CHANGELOG.md](CHANGELOG.md). Не создавайте отдельный файл журнала для каждой небольшой правки: добавляйте заметки в существующий журнал, а подробный diff оставляйте в истории Git.
