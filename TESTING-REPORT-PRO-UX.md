# Проверка UX библиотеки — версия 1.5.0

## Выполненные проверки

- `node --check server.js` — успешно.
- Все встроенные JavaScript-блоки `public/index.html` извлечены и проверены через `node --check` — успешно.
- JSON parsing: `builtin-tests.json`, `admin-credentials.json`, `package.json`, `examples/builtin-tests.example.json` — успешно.
- PostCSS parse: `public/ui.css`, `public/liquid-glass.css`, `public/tailwind.css`, `src/input.css` — успешно.
- CSS braces — совпадают.
- Проверено, что старый mode picker отсутствует в клиентском JavaScript/HTML, а его неиспользуемые CSS-правила удалены.
- Проверено, что режим выбирается в панели библиотеки до запуска, выбор хранится в localStorage, а карточка запуска напрямую загружает тест и вызывает `start(libraryLaunchMode)`.
- Проверены icon-only действия запуска, редактирования и копирования с `title` и `aria-label`.
- Проверен сценарий создания теста из открытой папки: `editorFolderId` передаётся в `lib/create`, сервер валидирует папку и сохраняет `folderId` вместе с тестом.
- Повторный end-to-end прогон на свежей копии прошёл: главная страница и статический CSS отвечают `200`; вход администратора; создание/переименование/удаление папки; создание/редактирование/копирование/перемещение/удаление теста; запуск комнаты Classic и Color Kingdoms; после удаления папки тесты остаются в библиотеке и переходят в «Без папки».
- HTTP-проверки на тестовом сервере: `/` возвращает `200 text/html`, `/liquid-glass.css?v=7` возвращает `200 text/css`.

## Ограничения

Полный визуальный сценарий взаимодействия в Chromium не удалось автоматизировать: headless Chromium зависает в этой среде из-за ограничений системной графической/DBus-инфраструктуры. Внешний Render-сервис и реальный GitHub-репозиторий изолированным тестом не изменялись.
