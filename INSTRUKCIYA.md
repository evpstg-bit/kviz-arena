# Инструкция: личный кабинет и запуск сервера

## Вход администратора после перезапуска Render

В архив добавлен файл **`admin-credentials.json`** с постоянными учётными данными администратора:

- Логин: `bntu`
- Пароль: `230825`

На сервере этот аккаунт создаётся из файла при каждом запуске и не зависит от `data/users.json`. Токен входа подписывается сервером и может пережить обычный перезапуск Render, даже если папка `data` очищается. После входа автоматически открывается личный кабинет с разделами встроенных/сохранённых тестов и личной библиотеки.

**Безопасность:** пароль хранится в файле проекта открытым текстом, поскольку этого требует текущая настройка. Не оставляйте публичный GitHub-репозиторий с этим файлом: любой сможет посмотреть пароль и войти. Перед публикацией сделайте репозиторий приватным или замените пароль на переменную окружения Render.


## 1. Как это устроено

- Для администратора используется постоянный логин и пароль из `admin-credentials.json`. Другие преподавательские аккаунты доступны только если включена регистрация через `INVITE_CODE`.
- Встроенные/проектные тесты всегда загружаются из файлов в репозитории. Личная библиотека хранится в `DATA_DIR`; на бесплатном Render это временное хранилище, если не настроен постоянный диск или база данных.
- Студентам аккаунт **не нужен**: они заходят по QR-коду или PIN.
- Каждый преподаватель видит только **свои** личные тесты.
- **Встроенные тесты** хранятся в файле `builtin-tests.json`, а экспортированные тесты, которые нужно закрепить в проекте, — в `saved-tests.json` в корне проекта. Оба файла входят в деплой и не исчезают после перезапуска Render. Они доступны только для запуска; чтобы изменить тест через интерфейс, нажмите «В мои тесты» и редактируйте копию.
- **Сервер** — это компьютер, на котором запущена команда `node server.js`. Он должен быть включён и доступен с тех компьютеров, откуда вы входите. Главный вопрос настройки — *где его запустить*.

| Вариант | Подходит, если | Откуда доступен | Где лежат тесты |
|---|---|---|---|
| **A. Один компьютер в школе** | вы работаете в одной сети (класс, кабинет) | из локальной сети по адресу вида `http://192.168.1.5:3000` | на этом компьютере |
| **B. Постоянный сервер (VPS)** ⭐ | нужен доступ из дома и из школы, несколько преподавателей | из интернета по адресу `https://quiz.ваш-домен.ru` | на сервере |
| **C. Временный (Codespaces и т. п.)** | хотите просто попробовать | по ссылке, пока сервер запущен | пропадут при удалении — делайте «Экспорт» |

Если не знаете, что выбрать: **для одного кабинета — вариант A, для работы из разных мест — вариант B**.

## 2. Как добавить тесты, встроенные в проект (Codespaces / Render)

Этот способ подходит, если тесты должны быть доступны из самого проекта и не исчезать на бесплатном Render после перезапуска. В корне проекта есть два файла — **`builtin-tests.json`** и **`saved-tests.json`**. По умолчанию оба пустые.

**Самый простой способ — через редактор игры:**
1. Откройте игру, войдите в аккаунт и создайте или импортируйте нужные тесты обычным способом.
2. В личном кабинете нажмите **«⬇ Экспорт»**. Браузер скачает `moi-testy.json` со всеми вашими личными тестами.
3. В Codespaces откройте `builtin-tests.json`. Замените его содержимое содержимым `moi-testy.json` и сохраните файл. Это безопасно: сервер принимает такой формат.
4. Сохраните изменения в GitHub (commit/push). Если Render связан с репозиторием, дождитесь автоматического деплоя; иначе запустите **Manual Deploy → Deploy latest commit** в панели Render.
5. Откройте кабинет в новой версии игры. Тесты появятся в блоке **«📦 Встроенные и сохранённые в проекте тесты»**. Их можно запускать, а кнопка «В мои тесты» создаёт редактируемую копию в личной библиотеке.

Можно также заполнить массив `items` вручную. Формат каждого теста показан в `examples/builtin-tests.example.json`; пример вопросов можно заменить своими. Каждый тест должен содержать `title`, `T`, `mode`, `dur`, `need` и массив `q`. В каждом вопросе нужны текст `t`, варианты ответов `a` и массив индексов правильных ответов `cs` (индексы начинаются с нуля). Один тест — максимум 100 вопросов.

**Важно:** тесты в `builtin-tests.json` и `saved-tests.json` сохраняются в исходниках проекта, но изменения из Codespaces не попадают на Render автоматически без commit/push и деплоя. Вход администратора `bntu` / `230825` управляется файлом `admin-credentials.json` и восстанавливается на каждом запуске; его подписанная сессия сохраняется при обычном рестарте. Остальные пользовательские аккаунты и личная библиотека по-прежнему используют `DATA_DIR`; на бесплатном Render это временное хранилище. Чтобы личные тесты не пропадали без экспорта в `saved-tests.json`, нужен постоянный диск/база данных и настройка сервера.

## 3. Вариант A. Один компьютер (самый простой)

1. Установите **Node.js** (версия LTS) с сайта https://nodejs.org.
2. Распакуйте архив `kviz-arena.zip` в любую папку.
3. Откройте папку и запустите сервер.
   - **Windows:** кликните в адресную строку проводника, введите `cmd`, нажмите Enter, затем введите `node server.js`.
   - **macOS / Linux:** откройте терминал в папке и введите `node server.js`.
4. В окне появятся адреса, например:
   ```
   Квиз-арена запущена: http://localhost:3000
   В локальной сети:  http://192.168.1.5:3000
   Аккаунтов: 1 (регистрация закрыта) — администратор загружается из `admin-credentials.json`.
   ```
5. Откройте `http://localhost:3000` → **«Войти / Регистрация»** и войдите логином `bntu`, паролем `230825`. Если измените данные в `admin-credentials.json`, используйте новые значения.
6. Нажмите «＋ Новый тест» и создайте тест (или импортируйте из Excel), нажмите **«💾 Сохранить»**.

**Как войти с другого компьютера в этой же сети:** откройте в его браузере адрес из строки «В локальной сети» (например, `http://192.168.1.5:3000`), нажмите «Войти» и введите тот же логин и пароль.

**Если Windows спрашивает про брандмауэр** — нажмите «Разрешить доступ».

**Если с других устройств не открывается:**
- убедитесь, что устройства в той же сети (гостевая Wi-Fi часто изолирует устройства друг от друга; тогда включите «Мобильный хот-спот» на компьютере с сервером);
- проверьте адрес: компьютер мог получить новый IP — смотрите строку «В локальной сети» при запуске.

**Ограничение:** пока этот компьютер выключен или окно с сервером закрыто, кабинет недоступен. Папка `data` рядом с `server.js` — это ваши аккаунты и тесты, не удаляйте её.

## 4. Вариант B. Постоянный сервер (VPS) — рекомендуется

Так кабинет работает всегда, из любого места, даже когда ваш компьютер выключен. Нужен недорогой сервер (VPS) на Ubuntu: подойдут Timeweb, Selectel, Beget, Reg.ru, VK Cloud и др. Минимальной конфигурации (1 ядро, 1 ГБ памяти) достаточно.

### Шаг 1. Закажите сервер и домен
1. Закажите VPS с **Ubuntu 22.04 или 24.04**. Запишите **IP-адрес** и пароль пользователя `root`.
2. (Рекомендуется) Зарегистрируйте домен или используйте существующий. В DNS-настройках домена создайте запись:
   - тип **A**, имя `quiz` (получится `quiz.ваш-домен.ru`), значение — IP вашего сервера.
   - Домен нужен, чтобы включить **HTTPS** (защищённое соединение) — это важно, если вы входите по паролю через интернет. Изменения DNS применяются от нескольких минут до пары часов.

### Шаг 2. Подключитесь и установите программы
С вашего компьютера (Windows 10/11: PowerShell, macOS/Linux: терминал):
```
ssh root@IP-ВАШЕГО-СЕРВЕРА
```
На сервере выполните:
```
apt update && apt install -y unzip curl nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
npm install -g pm2
```

### Шаг 3. Загрузите проект
Откройте **второе** окно терминала на вашем компьютере (не на сервере) и отправьте архив:
```
scp kviz-arena.zip root@IP-ВАШЕГО-СЕРВЕРА:/root/
```
Затем на сервере:
```
mkdir -p /opt/kviz /var/lib/kviz
cd /opt/kviz && unzip /root/kviz-arena.zip
```
`/opt/kviz` — программа, `/var/lib/kviz` — **данные** (аккаунты и тесты). Данные хранятся отдельно, поэтому обновление программы их не затрагивает.

### Шаг 4. Настройте и запустите
Откройте файл настроек:
```
nano /opt/kviz/ecosystem.config.js
```
- `DATA_DIR` оставьте `/var/lib/kviz`.
- `INVITE_CODE` — придумайте код, **если** аккаунты нужны нескольким преподавателям (они вводят его при регистрации). Если вы один — оставьте пустым: после создания первого аккаунта регистрация закроется.

Сохраните (Ctrl+O, Enter, Ctrl+X) и запустите:
```
cd /opt/kviz
pm2 start ecosystem.config.js
pm2 save
pm2 startup
```
Команда `pm2 startup` выведет строку — скопируйте её и выполните. После этого сервер сам запускается при перезагрузке.

Проверка: `pm2 status` должен показать `kviz` в состоянии `online`.

### Шаг 5. Подключите домен и HTTPS
Создайте файл:
```
nano /etc/nginx/sites-available/kviz
```
Вставьте (замените адрес на свой):
```
server {
  listen 80;
  server_name quiz.ваш-домен.ru;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_buffering off;
    proxy_read_timeout 1h;
  }
}
```
> Строки `proxy_buffering off` и `proxy_read_timeout` **обязательны**: без них игра будет «зависать» и обновляться с задержкой.

Включите и получите бесплатный сертификат:
```
ln -s /etc/nginx/sites-available/kviz /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
apt install -y certbot python3-certbot-nginx
certbot --nginx -d quiz.ваш-домен.ru
```
Убедитесь, что в панели хостинга (и в брандмауэре, если он включён: `ufw allow 80,443/tcp`) открыты порты **80** и **443**.

### Шаг 6. Первый вход
Откройте `https://quiz.ваш-домен.ru` → «Войти / Регистрация» → войдите логином `bntu`, паролем `230825`. Если изменили данные в `admin-credentials.json`, используйте обновлённые значения после деплоя.

Если домена нет, сервер доступен по `http://IP-ВАШЕГО-СЕРВЕРА:3000` (откройте порт 3000 в брандмауэре). Но пароль при этом передаётся без шифрования — для постоянной работы лучше настроить HTTPS.

### Резервные копии
Всё важное лежит в `/var/lib/kviz`. Простая ежедневная копия:
```
crontab -e
```
добавьте строку:
```
0 3 * * * tar czf /root/kviz-backup-$(date +\%F).tgz /var/lib/kviz
```
Периодически скачивайте копии на свой компьютер. Дополнительно в кабинете есть кнопка **«⬇ Экспорт»** — она сохраняет все ваши тесты в один файл.

### Обновление программы
Загрузите новый архив на сервер, распакуйте поверх `/opt/kviz` (`unzip -o /root/kviz-arena.zip -d /opt/kviz`), затем:
```
pm2 restart kviz
```
Аккаунты и тесты сохранятся (они в `/var/lib/kviz`). Файл `ecosystem.config.js` при распаковке перезапишется — проверьте настройки.

## 5. Вариант C. Временный запуск (Codespaces и подобное)

Подходит только чтобы попробовать. Тесты и аккаунты лежат в файлах внутри временного окружения и **исчезнут**, если его удалить или оно будет сброшено. Поэтому после работы нажимайте в кабинете **«⬇ Экспорт»** и сохраняйте файл у себя; в новом окружении восстановите тесты кнопкой **«⬆ Импорт»**. То же относится к бесплатным тарифам хостингов с временной файловой системой (например, бесплатный тариф Render).

## 6. Несколько преподавателей

- Первый аккаунт — администратор.
- Задайте `INVITE_CODE` (в `ecosystem.config.js` или при запуске: `INVITE_CODE=секрет node server.js`) и раздайте этот код коллегам. Они регистрируются сами: вкладка «Регистрация» → логин, пароль и **код приглашения**.
- Тесты у каждого свои, чужие не видны. Отправить тест коллеге можно через «Экспорт» → файл → «Импорт».
- Если код не нужен, уберите его — регистрация снова закроется.

## 7. Забыли пароль

На компьютере/сервере, где лежит сервер, выполните (с тем же `DATA_DIR`, что и при запуске):
```
node server.js --users
node server.js --reset-password ЛОГИН НОВЫЙ_ПАРОЛЬ
```
Первая команда покажет логины. Для аккаунта `bntu` пароль задаётся в `admin-credentials.json`, поэтому обновите этот файл и выполните деплой. Для другого аккаунта вторая команда задаст новый пароль и сбросит его обычные сессии. Например, на сервере из варианта B: `cd /opt/kviz && DATA_DIR=/var/lib/kviz node server.js --reset-password ivanova новыйпароль1`.

## 8. Перенос на другой сервер

Скопируйте папку данных (`data` или `/var/lib/kviz`) на новое место и укажите её в `DATA_DIR` — все аккаунты и тесты сохранятся. Либо воспользуйтесь «Экспорт» / «Импорт» в кабинете (перенесутся тесты, но не аккаунты).

## 9. Безопасность

- Пароли хранятся в зашифрованном (хэшированном) виде, после 5 неверных попыток вход блокируется на минуту.
- Правильные ответы студентам не передаются до конца вопроса.
- При работе через интернет используйте **HTTPS** (шаг 5 варианта B).
- Создавать игры могут только вошедшие в аккаунт.

## 10. Частые проблемы

| Проблема | Что делать |
|---|---|
| Студенты не могут открыть адрес | Проверьте, что они в той же сети (вариант A) или что открыты порты 80/443 (вариант B); сверьте адрес со строкой «В локальной сети» |
| «Регистрация закрыта» | Аккаунт администратора уже создан. Задайте `INVITE_CODE` и перезапустите сервер |
| Игра обновляется с задержкой за nginx | Добавьте `proxy_buffering off;` в настройки (шаг 5) |
| «Сессия истекла — войдите снова» | Нажмите «Войти» заново; входы действуют 60 дней |
| Пропали тесты после перезапуска | Сервер запускается с другой папкой данных — проверьте `DATA_DIR`; на бесплатных хостингах диск временный |
| Хочу посмотреть, что с сервером | `pm2 logs kviz` |


## Светлая и тёмная темы

В правом верхнем углу сайта есть переключатель «🌙 Тёмная тема» / «☀ Светлая тема». Нажмите его, чтобы сменить оформление. Выбор хранится в браузере и сохраняется после обновления страницы. Настройка применяется ко всем экранам игры на этом устройстве.

В CSS используется класс `dark` на корневом элементе страницы (`html`). При изменении стилей запускайте `npm run build:css`, чтобы обновить `public/tailwind.css`. У вторичных кнопок отдельные hover-цвета: в светлой теме — светло-серый фон с тёмным текстом, в тёмной — тёмно-серый фон со светлым текстом; это предотвращает слияние белого текста с белым фоном.


## Новая дизайн-система интерфейса

Для современного адаптивного оформления добавлен файл `public/ui.css`. Он содержит общую палитру, стили светлой и тёмной тем, компоненты главной страницы, авторизации, библиотеки тестов и адаптацию для телефонов. Файл подключается через `/ui.css`; в `server.js` добавлен маршрут статического файла. При деплое убедитесь, что `public/ui.css`, `public/index.html` и `server.js` отправлены в одну ветку GitHub.

В личном кабинете доступны поиск по названию/режиму и фильтры «Все», «В проекте» и «Мои». Быстрый переход к строке поиска — Ctrl+K или ⌘K.
