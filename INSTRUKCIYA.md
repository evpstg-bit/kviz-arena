## 2. Как устроена библиотека

Единственный источник тестов — `builtin-tests.json` в корне проекта. В личном кабинете можно импортировать Excel, редактировать тесты, создавать копии и удалять их. Все эти операции изменяют проектный файл, а не временную личную библиотеку в `DATA_DIR`.

**Важно о Render:** файловая система обычного сервиса может быть временной. Чтобы изменения из интерфейса автоматически попадали именно в репозиторий, а не только в запущенный процесс, настройте GitHub auto-sync (см. подраздел «Автоматическая запись в GitHub / Render» ниже). После этого сервер создаёт коммиты для `builtin-tests.json`, а Render получает их при автодеплое. Если синхронизация не настроена, сервер изменит файл в текущей рабочей папке и скачает резервную копию; на Render без GitHub auto-sync её нужно перенести в репозиторий вручную.

## 3. Импорт XLSX и управление тестами

### Формат Excel

Один лист XLSX = один тест. Можно использовать файл `examples/primer-voprosov.xlsx` как образец. В таблице должны быть заголовки:

- `Question` / `Вопрос`;
- `Answer 1` … `Answer 4` или `Вариант 1` … `Вариант 4`;
- `Time limit` / `Время` (необязательно);
- `Correct answer(s)` / `Правильные ответы`.

Заголовки могут находиться ниже инструкций в начале листа — импортёр самостоятельно ищет строку заголовков. В поле правильных ответов указывайте номера вариантов с единицы (`2` означает второй вариант; `1,3` означает первый и третий) или буквы `A`–`D`. Вопросы без двух непустых вариантов и корректного ключа пропускаются; предупреждения показываются после импорта. Поддерживаются `.xlsx`, `.xls` и совместимый `.json`.

### Импорт и изменение тестов

1. Войдите под аккаунтом администратора.
2. В библиотеке нажмите **↑ Импорт** и выберите Excel-таблицу. Каждый лист с распознаваемой таблицей вопросов станет отдельным тестом.
3. Тесты добавляются к существующим в `builtin-tests.json` и появляются в списке. Повторный импорт создаёт новые тесты, не заменяя старые.
4. У карточки теста доступны **Редактировать**, **Копировать** и **Удалить**. В редакторе можно менять название, режим, время, вопросы, варианты и правильные ответы.
5. **↓ Экспорт** скачивает весь текущий `builtin-tests.json`, включая идентификаторы тестов. Это резервная копия и способ перенести файл.

### Автоматическая запись в GitHub / Render

Чтобы импорт, редактирование, копирование и удаление гарантированно сохранялись в репозитории после перезапуска Render:

1. На GitHub создайте fine-grained Personal Access Token для нужного репозитория. Дайте только разрешение **Contents: Read and write**.
2. На Render откройте **Dashboard → ваш сервис → Environment** и добавьте:
   - `GITHUB_TOKEN` — токен (секретное значение);
   - `GITHUB_REPOSITORY` — имя репозитория в формате `владелец/репозиторий`;
   - `GITHUB_BRANCH` — ветка, которую разворачивает Render (обычно `main`).
3. Сохраните переменные и перезапустите сервис.
4. После этого изменения через кабинет будут коммититься в `builtin-tests.json` в указанной ветке. Не помещайте токен в `server.js`, `admin-credentials.json`, `render.yaml` или любой файл репозитория.

Если эти переменные не настроены, при каждой операции файл записывается в рабочую директорию процесса и кабинет скачивает свежую резервную копию `builtin-tests.json`. В локальном Codespaces затем можно выполнить Commit & Push. На Render без настройки GitHub API изменения в контейнере не гарантированно сохранятся при следующем деплое.

## 4. Структура `builtin-tests.json`

Файл имеет следующую форму:

```json
{
  "app": "kviz-arena",
  "version": 2,
  "items": [
    {
      "id": "test-example",
      "quiz": {
        "title": "Пример теста",
        "T": 20,
        "mode": "classic",
        "dur": 5,
        "need": 3,
        "q": [
          {
            "t": "Какой язык выполняется в Node.js?",
            "a": ["JavaScript", "CSS", "HTML", "SQL"],
            "cs": [0],
            "T": 20
          }
        ]
      }
    }
  ]
}
```

Поля теста:

- `title` — название теста, максимум 80 символов;
- `T` — общее время на вопрос в секундах, например `20`;
- `mode` — `classic` или `kingdoms`;
- `dur` — продолжительность Color Kingdoms в минутах от 1 до 10;
- `need` — количество правильных ответов для установки флага;
- `q` — список вопросов, максимум 100 в одном тесте.

Поля вопроса:

- `t` — текст вопроса;
- `a` — 2–4 варианта ответа, все непустые;
- `cs` — массив индексов правильных ответов, начиная с нуля: `[0]` означает первый вариант, `[1, 3]` — второй и четвёртый;
- `T` — необязательное время на конкретный вопрос в секундах.

Пример структуры также есть в `examples/builtin-tests.example.json`. Сам пример не загружается автоматически в игру — копируйте его в `items`, когда нужно добавить демонстрационный тест.

## 6. Если тест не отображается

1. Проверьте валидность JSON: все кавычки двойные, элементы разделены запятыми, после последнего элемента запятой нет.
2. Убедитесь, что файл называется точно `builtin-tests.json` и находится в корне рядом с `server.js`.
3. Убедитесь, что изменения отправлены в правильную ветку GitHub, подключённую к Render.
4. Проверьте успешный деплой и логи сервера. При запуске сервер выводит количество тестов, загруженных из `builtin-tests.json`, и предупреждения о пропущенных тестах.
5. Обновите страницу игры после завершения деплоя.

## 7. Локальный запуск

Требуется Node.js 18 или новее. В папке проекта выполните:

```bash
node server.js
```

Затем откройте `http://localhost:3000`. Для учётной записи используются данные из `admin-credentials.json`. Если Codespaces или Render уже запускают приложение, отдельный локальный запуск не требуется.

## 8. Деплой на Render

При настроенном `GITHUB_TOKEN` изменения `builtin-tests.json` автоматически коммитятся в заданную ветку, после чего Render может начать автодеплой. При ручном управлении изменениями используйте Codespaces → Commit & Push и дождитесь деплоя. Если автодеплой выключен: Render Dashboard → сервис → **Manual Deploy → Deploy latest commit**.

## 9. Темы и минималистичный интерфейс

Светлая и тёмная темы переключаются кнопкой в правом верхнем углу. Выбранный режим сохраняется локально в браузере. Файл `public/ui.css` содержит стили интерфейса и может редактироваться без пересборки Tailwind. При изменении Tailwind-учебная группаов в `public/index.html` или `src/input.css` выполните `npm install && npm run build:css`.

В кабинете кнопки «↓ Экспорт», «↑ Импорт», «На главную» и «Выйти» расположены в верхней панели. Внизу страницы отображается подпись `© eyefront` — активная ссылка на https://www.instagram.com/eyefront/ (открывается в новой вкладке).

## 8. Визуальный стиль Liquid Glass

В этой версии добавлен отдельный файл `public/liquid-glass.css`. Он подключается после `ui.css`, поэтому стеклянные поверхности, мягкие фоновые ореолы, блики, размытые карточки и новые состояния элементов видны поверх прежнего оформления. Логику игры, тесты и систему переводов этот слой не меняет.

Если вы изменяете стили через Tailwind, не удаляйте ссылку на `/liquid-glass.css`: она подключается последней намеренно. Пересборка Tailwind не генерирует и не перезаписывает этот файл. В браузерах без поддержки `backdrop-filter` включается более плотный фон; при системной настройке уменьшения движения фоновая анимация отключается.
